# ADR 1: no credential ever enters Terraform state

## Status
Accepted

## Context
The usual way to give RDS a password is `random_password` →
`aws_db_instance.password` → `aws_secretsmanager_secret_version.secret_string`.
Every one of those stores the plaintext value in Terraform state, and
usually in the saved plan file too. State then becomes a credential store
by accident. Anyone who can read the state bucket, or a CI log that
printed a plan, has the database password, the Redis auth token and here
also hookrelay's admin key, which can create API keys for any tenant.

Terraform 1.11 added write-only arguments, which are sent to the provider
and never persisted, and ephemeral resources, whose values exist only for
the duration of one run. The AWS provider (6.x) has write-only variants of
all three arguments this module needs: `password_wo`, `auth_token_wo` and
`secret_string_wo`. That was checked against the provider schema, not
assumed.

## Decision
The database password, the Redis auth token and the admin API key are
each generated by an `ephemeral "random_password"`. Each is passed to AWS
only through a write-only argument. Each is written once to Secrets
Manager (the database and Redis values as complete connection URLs), and
ECS injects them into the containers from there. The admin key is not an
output; the output is the ARN of the secret holding it.

Verified on the example's real plan: `password`, `password_wo`,
`auth_token`, `auth_token_wo`, `secret_string` and `secret_string_wo` are
all `null` in `terraform show -json`. The plan records only the
`*_wo_version` numbers.

## Consequences
- **Rotation is a version bump, not an edit.** Ephemeral values change on
  every run, so write-only arguments are applied only when their
  `*_wo_version` changes. `credentials_version` drives all three together.
  Bumping it generates new values, sets them on RDS and ElastiCache, and
  rewrites the secrets in the same apply. Running tasks keep the old
  values until they restart, so rotation needs a new deployment of both
  services right after the apply. The README says so.
- **Terraform can never show you a credential.** That's the point, and
  it's a real inconvenience the first time someone wants the admin key:
  they read it from Secrets Manager with their own IAM permissions.
- **Requires Terraform 1.11+ and AWS provider 6.x**, both pinned in
  `versions.tf`. Older tooling can't run this module at all, instead of
  running it and leaking.
